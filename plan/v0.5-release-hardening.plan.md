# v0.5.0 Release-Blocking Architecture Hardening Plan

## Goal

Pause the v0.5.0 release train and reduce maintainability risk in CLI orchestration, DB hook lifecycle coverage, storage layout, E2E assertions, and command tests before release validation resumes.

## Scope

- Extract diagnostic and session-inspection logic out of `cmd`.
- Add missing TCP proxy flush lifecycle coverage.
- Split `FileStore` implementation files without changing storage behavior.
- Move official E2E assertion and summary parsing into a Go helper.
- Split large command tests by command.
- Keep all work on short-lived branches into `dev`; no promotion, tag, or release without explicit approval.

## Approach

- Deliver the hardening as five focused PRs, each based on latest `origin/dev`.
- Preserve CLI flags, config schema, storage JSON/JSONL shape, and current session/report output contracts.
- Prefer behavior-preserving refactors first, then lifecycle tests and tool hardening.
