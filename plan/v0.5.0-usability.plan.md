# v0.5.0 Usability and Acceptance Plan

## Goal

Make the v0.4 typed side-effect architecture easier to diagnose, inspect, and validate with release binaries.

## Scope

- Add `shadiff doctor` for read-only environment diagnostics.
- Improve the official E2E demo runner output and machine-readable summary artifacts.
- Add session inspection and side-effect difference summaries to reports.
- Add a manual GitHub Actions workflow for the official E2E demo.
- Keep all work on short-lived branches into `dev`; no promotion, tag, or release without explicit approval.

## Approach

- Implement each capability in a separate PR so `dev` remains easy to review.
- Keep default unit tests Docker-free.
- Preserve the current v0.4 typed side-effect JSON contract and avoid legacy session compatibility.
- Treat official E2E as an explicit/manual acceptance path rather than a default PR gate.

- [x] Add `shadiff doctor` with terminal/JSON output, strict mode, and optional E2E port checks.
