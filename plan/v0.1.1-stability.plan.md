# v0.1.1 Stability Plan

## Goal

Harden the CI and release pipeline, add Docker-backed DB side-effect integration coverage, and publish `v0.1.1` through the normal `dev` to `main` promotion flow.

## Scope

- Upgrade GitHub Actions workflow actions to Node24-compatible major versions.
- Verify release assets before upload.
- Upgrade the repository and workflows to Go 1.25 so the latest Docker-backed integration test dependencies can be used.
- Add Docker-backed integration tests for MySQL, PostgreSQL, MongoDB, and a lightweight side-effect diff loop.
- Publish `v0.1.1` after all checks pass.
- Do not change CLI flags, config schema, or the `DBHook` public interface.

## Approach

1. Land CI and release hardening on `chore/ci-node24-release-smoke`.
2. Land DB side-effect integration tests on `test/db-sideeffects-integration`.
3. Promote `dev` to `main`, tag `v0.1.1`, and let the release workflow build and verify assets.

## Verification

```bash
go test ./...
go build -o shadiff .
bash scripts/verify-release-assets.sh dist v0.1.1
go test -v -tags integration ./internal/integration -count=1 -timeout=20m
gh release view v0.1.1 --json assets,url,tagName
```

Local integration tests skip when Docker is not available; GitHub Actions runs the same command with `CI=true`, where Docker unavailability is treated as a failure.
